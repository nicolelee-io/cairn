- Search scroll and Calendar menu (2026-11-12): opening an entry from Search (or any deep link) now scrolls the List view to its card, loading further pages until it appears. `useRevealEntry` was comparing the card with its month's `section` instead of the scrolling Entries pane, so it always judged the card on screen; it now uses the pane. The month jump replaced the planned scrubber, so nothing is shared with it. Calendar days with entries have a context menu (`DayCell` in `CalendarView.tsx`): a one-entry day gets the entry menu (Edit, Pin, Star, Move, Export, Delete), a day with several lists them by time and title. The day's entries are fetched when the pointer or focus reaches the day, and `invalidateAfterSave` now refreshes `keys.insights` so the calendar follows a change made from its menu. Other Entries views (Calendar, Media, Map, Details) don't scroll the list, as it isn't shown. Not checked on a real phone.
- Weather reused from the preview (2026-11-12): Save no longer asks the provider a second time. `weather/cache.ts` `withWeatherCache` keeps the provider's answers for 10 minutes (keyed by provider, exact coordinates and the entry's 10-minute bucket), the editor's preview fills it, and on a create or PATCH `routes/entries.ts` stores the cached weather before building the response (`refreshWeatherFromCache`), so the reader opens with the chip instead of showing it a few seconds later. On a miss (preview unfinished, an offline queue replay, a time edited since) it falls back to the background fetch. The stored row is still the server's own, so it stays automatic and follows a later change of place or time. Choosing Google as the weather source now says plainly that it only has the last 24 hours, and the Google key text says the Weather API is optional.
