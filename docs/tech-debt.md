# Bugs and tech debt

Things that are wrong or fragile: bugs, and known issues that are too small, or too early, to fix now. Features and ideas live in [todo-and-ideas.md](todo-and-ideas.md). **Before changing a component, search this file for its name or area** and fix the item in the same change if it is cheap or touches the code you are already editing. Remove an entry when it is fixed. Many entries came from a whole-repo review on 2026-10-29.

Format: **area**: problem. _Fix_: what to do. _Look at this when_: the trigger. A bug can be just the problem and how to reproduce it. _Est_: suggested model and size (see the legend in [todo-and-ideas.md](todo-and-ideas.md): Sonnet for well-scoped work, Opus for security, data-safety or cross-cutting work; XS under 30 min, S 1-2 h, M half a day, L 1-2 days).

## Bugs

- **Flaky e2e under the full run: search (phone) and keyboard (desktop)** (`e2e/search.spec.ts:7`, `e2e/keyboard.spec.ts:7`): in one full `npm run e2e` (2026-11-04, 147 passed) "find an entry by a word and open it" on the phone didn't show the heading within 5s, and "a keyboard-only session" on desktop timed out waiting for its entry card at `/j/<id>`. Both passed on a rerun of just those two specs, so it looks like load, not the code (the prompts work touched the nav and bottom bar, which both specs use, so rule that out first if they fail again). _Fix_: find out what is slow on a cold journal list under two workers. _Look at this when_: either spec fails in a full run. Two full runs on 2026-11-05 (157 passed each) were clean after the drawer's stale `close` event was fixed, which may have been the cause (both specs go through the nav); not reproduced since (a full run on 2026-11-14 passed 214, 0 failed), so leave this until it fails again. Also once on 2026-11-05: "Ctrl+S saves and stays in the editor" (phone, `e2e/entry.spec.ts:49`) showed the reader without the last typed paragraph in a full run; `entry` passed 19 of 19 with `--repeat-each=2` right after.

## Server

- **Images carry no OCI labels** (`.github/workflows/ci.yml`): the build steps don't pass `docker/metadata-action`'s `labels` output, so neither image has `org.opencontainers.image.source`, `revision` or `version`, and a package isn't linked to the repo by its label. _Fix_: add `labels: ${{ steps.meta.outputs.labels }}` (and `steps.meta-backup.outputs.labels`) to the two `build-push-action` steps. _Look at this when_: next touching CI. _Est: Sonnet, S._
- **Journal delete is O(entries)** (`repo/journals.ts`, and its restore in `repo/trash.ts`, which also bumps each entry's photos and attachments): one update plus `nextRev` per row. Correct (per-row revs matter for sync) but slow for very large journals. _Look at this when_: building sync, or deleting a big journal feels slow. _Est: Opus, M (it must keep per-row revs for sync, so a batch version needs care; not worth doing until it is slow)._
- **Cookie name** (`auth/middleware.ts`): could be `__Host-cairn_session` for extra hardening, but that requires `Secure`, which plain-http access (on a LAN or over a VPN) doesn't have. _Look at this when_: dropping plain-http access. _Est: Sonnet, XS (the rename logs everyone out once)._
- **Export hashes every photo before it starts** (`export/run.ts`, attachments too): each original is read once for its md5 and again to be zipped, and the download only begins after the first pass, so a large library is slow to start. _Fix_: store the md5 on the photo row at upload (a migration) so the first pass disappears. _Look at this when_: exporting feels slow, or touching the photo schema. _Est: Sonnet, M (migration, upload path, and a backfill for existing photos)._
- **Security review, accepted as is** (2026-11-14, here so they aren't rediscovered): `isHttps` believes `X-Forwarded-Proto` without `TRUST_PROXY` (a client can only change the `Secure` flag on its own cookie); an admin can point the ntfy URL at an internal address (admin only, POST only, no redirects, response discarded); unsent drafts and the outbox stay in the browser after sign-out (by design); an imported attachment that fails the type check keeps its declared type (served `nosniff` under a restrictive CSP, to its owner only). _Look at this when_: the threat model changes (public signup, sharing). _Est: none needed._
- **Weather polling after save** (`components/EntryReader.tsx`) re-fetches the entry a few times because the background fetch can't push. _Fix_: none needed online; the sync feed carries weather (`weather_rev`) to journals kept offline. _Look at this when_: weather or the entry query changes. _Est: none needed (no fix planned)._

## Web

- **Place dialog scrolls sideways by 4px** (`components/editor/LocationDialog.tsx`): the dialog body (`px-1`, in `ui/dialog.tsx`) is 4px narrower than the Recent and results lists' `-mx-2`, so `scrollWidth` is 412 against 408 and a thin horizontal scrollbar shows at the bottom of the dialog (seen 2026-11-12 in the verify-ui instance, with or without the place-name field). _Fix_: use `-mx-1` on those lists, or stop the lists bleeding past the body. _Est: Sonnet, XS._
