## Places

- `places/provider.ts` is the interface (`search`, `details`, `reverse`); `places/google.ts` implements it with Places API (New) autocomplete/details and the Geocoding API. `places/index.ts` (`googleKeys`) resolves the key on every call: a key saved in Settings (`app_setting` table, instance-wide so no `user_id`) wins over `GOOGLE_API_KEY`. `/api/places/key` (GET status / PUT / DELETE) never returns the key, only source and last four characters; `/api/places/{search,details,reverse}` answer 424 (never 502/503/504, which the web client reads as "server down") with `places_unavailable` for no key and `places_failed` when Google fails.
- Entries take `location` on create and PATCH (omit = unchanged, null = remove), written by `writeLocation` in `repo/entries.ts`, which re-indexes search. Photos expose EXIF `latitude`/`longitude` for "use this photo's location".
- Web: `editor/LocationDialog.tsx` (current location via browser geolocation, search with a per-open session token, photo GPS, remove), a place chip in the editor footer, and the key card in Settings. If reverse geocoding fails, the place is saved as bare coordinates. The Geocoding API must be enabled on the key's Google project.
- The Place dialog lists recent places before anything is typed (`GET /api/entries/recent-places`: distinct named places from the user's entries, newest entry first, max 8; under `keys.entries` so saves refresh it). Offline (`useServerDown()`, or a lookup that `isUnreachable`), the search box becomes an `OfflineNote`, and current location and photo GPS still work, offering "Save coordinates only" since only the address lookup needs the server; recent places show if the service worker has them cached.
- Drafts carry `location` (old drafts default to null).
