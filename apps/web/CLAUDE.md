# Web app

Vite + React SPA. Nearby notes: `src/components/editor/CLAUDE.md` (the editor) and `src/lib/CLAUDE.md` (PWA, local store, outbox, sync, offline reads).

Breakpoints (`index.css`): `medium` 600px, `expanded` 840px (two panes, `TWO_PANE` in `lib/pane.ts`), `large` 1200px (permanent sidebar). Phone first.

## Theme and styling

- Tailwind v4, CSS-first, no config file (`src/index.css`). Colours are Material 3 roles generated by `src/theme/buildTheme.ts` from one seed into the committed `src/theme/theme.css`; `index.css` exposes them as Tailwind colours (`bg-surface-container`, `text-on-surface-variant`) and under shadcn's variable names. Light and dark switch through the variables, so **never write `dark:` variants**. Settings can force either (`lib/theme.ts` sets `data-theme` on `<html>`, per device). `buildTheme.test.ts` asserts WCAG AA on the pairs the UI draws; add a pair when you introduce a new combination.
- `components/ui/*` are shadcn-style primitives written by hand (cva + tailwind-merge). `state-layer` is the M3 hover/press utility; its hover wash is only under `@media (hover: hover)`, since a touch screen leaves `:hover` stuck.
- Icons: `components/Icon.tsx` inlines only the Material Symbols Rounded SVGs in its glob and `ICON_NAMES`. Every name in `JOURNAL_ICONS` and `PROMPT_ICONS` (`packages/shared`) must be there too.
- Fonts: the UI is `font-sans` (system stack), entry text `font-entry`. A mood emoji takes `font-emoji` on an element holding only the emoji (`SelectOption`'s `emoji` in a `Select`), or a text font with its own monochrome emoji (DejaVu) wins.
- Loading: a wait that fills a pane, page or dialog is `LoadingState` (`components/Spinner.tsx`; `Spinner size="sm"` in a status line). Where the shape is known use `components/Skeleton.tsx` (`EntryListSkeleton`, the reader's `ReaderSkeleton`). Never a bare "Loading…" paragraph; button labels like "Saving…" are fine. The spinner's stones are `<g>`s because a CSS transform on the rects would replace their rotation attribute.
- Scrollbars are thin and themed globally; the window's own is hidden below 1200px so it can't shave width off the fixed bottom bar and FAB.

## Layout and navigation

- `layout/NavContent.tsx` is the one full nav: the permanent sidebar from `large`, a `NavDrawer` (native `<dialog>`) below, opened from each screen's `TopBar`. In the sidebar only the journal rows scroll, through `large:` classes in `NavContent` and `SidebarJournals`; keep new nav parts out of that container. Below `large`, Entries, Insights and Prompts are also a `BottomBar`.
- New entry is a FAB at every width (`NewEntryButton`). It goes to `/j/<journalId>/new` while a journal is browsed (`newEntryPath` in `lib/useBrowseParams.ts`), else `/new`, which uses `me.defaultJournalId` (resolved by the server). `lib/scrollChrome.ts` hides the bar on scroll down and brings it back on scroll up, ignoring scrolls the page makes itself (`ignoreScrollEvents`). The bar, FAB and toast positions follow `useBarVisible`; quiet pages (`quiet` in `useBrowseParams`) show neither bar nor FAB. The bar is `4rem + env(safe-area-inset-bottom)` tall (an `h-16` with the inset as padding got squashed once Chrome hid its address bar).
- Browse is master-detail (`layout/BrowseLayout.tsx`): the entry list beside a reader or editor pane, with the same URLs at every width (`/`, `/j/:journalId`, then `entry/:id`, `new` and `entry/:id/edit` under either). Below `expanded` one pane shows and the list stays mounted but hidden; from `expanded` each pane scrolls itself and the window doesn't. Derive journal and entry with `lib/useBrowseParams.ts` (`useMatch`; not `useParams` in layouts). Opening an entry while one is open beside the list uses `replace`. Pages outside browse wrap themselves in `<Page>` (max width, padding, menu button, optional `back`, `icon`, `wide`).
- Back (`lib/navigation.ts`) works like an app's. The history is a stack: Entries at `history.state.idx` 0, then one top-level screen, then drill-downs. Links to a top-level screen are `TopLink`s (`useTopNavigate`, finished by `NavigationSync` in `App.tsx`); every other link is a plain push. On-screen Back is `useGoBack` (`navigate(-1)` while `idx > 0`, else `parentOf(pathname)`); never hard-code a back path. A deep link gets its parents (`ancestorsOf`, unit-tested) filled in underneath; a new route outside Entries or Settings may need a case there.
- Android's Back closes a drawer, dialog or lightbox without navigating because they are native modal `<dialog>`s (Chrome sends them a `CloseWatcher` close request, which arrives like Esc). An overlay built from a div would need its own history handling.
- Whether the server answers is `lib/serverStatus.ts` (`api()` reports into it; `useServerDown()`), shown quietly and never as an alert; see "Refusals and status" in `src/lib/CLAUDE.md`.
- Keyboard access: `BottomBar` and `NewEntryButton` come after `<main id="main">` in the DOM so Tab meets the page first; `useFocusOnNavigate` moves focus to `main` when the pressed link went away; a Skip to content button leads. A `role="radiogroup"` (the view switch, Insights' range) is one tab stop (`radioKeys` in `lib/moveFocus.ts`, plus `data-owns-keys` so bare arrow shortcuts leave it alone). A dialog whose point is one text field sets `data-autofocus={autofocusWithMouse()}` (`lib/pointer.ts`; on touch it would raise the keyboard).

## Settings

- `layout/SettingsLayout.tsx` wraps `/settings`, `/settings/*` and the pages with their own URLs (`/journals`, `/tags`, `/templates`, `/trash`, `/storage`, `/users`, `/sync`). Below `expanded` the list and each page take the whole screen; from `expanded` the list (`pages/settings/SettingsNav.tsx`) sits beside the page, a row `replace`s it (one Back leaves Settings), and pages get `InSettingsPane`, which makes `TopBar` drop Back, search and the sync dot (`keepBack` keeps Back on a nested page such as Entry text). The `/settings/:section` pages are in `pages/settings/sections.tsx`; the server ones go through `ServerSettings` (admins only, hidden offline; the server refuses those routes anyway).
- A setting is a `SwitchSetting` or `ChoiceSetting` (`pages/settings/SettingRow.tsx`) with a `scope`: `account` (synced through `useUpdateMe`) or `device` (localStorage). A new setting says which, and goes on the page of its topic. A Settings list row has a short live line; keep it short, the desktop column truncates it.
- Offline: account settings and the default timezone queue in the outbox; the display name, username, password, picture and Sign out are disabled; the Server group is hidden; an `OfflineBanner` tops the list. A new account or server setting must follow that.
- Tips & tricks (`settings/TipsPage.tsx`) lists the gestures, menus and keys that aren't obvious, each tagged `touch`, `mouse` or `wide` and hidden where it can't be done. **When a gesture, menu or key changes, or a new hidden one is added, update its tip.**
- About (`AboutCard`) shows both builds, the license and `SOURCE_URL`, which a fork must point at its own repository, and the Open-Meteo credit.
- Changing the default timezone invalidates `keys.insights` (Insights and the Calendar bucket days in it).
- Server alerts (`AlertsCard`): the ntfy token field is a text input drawn as dots, and every field has `NO_AUTOFILL`, because a `type=password` field under a text field is taken for a login and autofilled.

## Data

- `lib/api.ts` (fetch + Zod from `@cairn/shared`) with TanStack Query. Every query key comes from `keys` in `lib/queries.ts`, never a literal; keys nest (`keys.entries` covers timelines, the map, media and recent places). `invalidateAfterSave` refreshes lists, search, counts, the trash and Insights after an entry save. A 401 anywhere flips `me` to null and `AuthGate` shows the login screen. Never `queryClient.clear()` on logout (it orphans mounted queries); see `useLogout`.
- Vite's `/api` proxy target is `API_URL` (default `http://localhost:3000`), so a second dev instance can run on other ports (`PORT=3100` for the server, `API_URL=http://localhost:3100 vite --port 5273`). Keep `changeOrigin: false`, or the server's Origin check 403s every dev POST.
- A page or block that needs the server shows `NeedsConnection` while `useServerDown()`; the full offline rules are in `src/lib/CLAUDE.md`.

## Dialogs, menus and buttons

- `components/ui/dialog.tsx` wraps native `<dialog>`: the title row and X stay pinned and only the body scrolls, so don't give a dialog its own overflow. `onClose` fires only for user closes (Esc, backdrop), not for the `open` prop, so one dialog can hand over to another. A `<dialog>`'s `close` event arrives as a later task: a handler that dismisses on it must check the dialog isn't open again by then (`Dialog` checks `open`, `NavDrawer` and `ContextMenu` check `e.currentTarget.open`). Focus starts on the title; `data-autofocus` moves it.
- **Button alignment:** dialog buttons go in `DialogActions` (right-aligned, main action last; `stacked` only when they don't fit side by side on a phone); a shortcut that fills the dialog's fields is a full-width tonal `Button` on its own row above them. Buttons in an inline card or form on a page are left-aligned, main action first (`flex flex-wrap gap-2`). A page's closing call-to-action pair is centred; menu-style rows of text buttons are `justify-start`. An "are you sure?" is a `ConfirmDialog`; don't hand-build one.
- A `Select`'s list is clipped by a dialog's edges, so a choice inside a dialog is chips (`FilterChips`) or a picker in its own stacked dialog (`TagPicker`, `TimezoneDialog`).
- Dialogs that sit inside a form (the editor's) must handle Enter in their inputs (`preventDefault`), never let it submit.
- **Context menus:** one menu for the app, `components/ContextMenu.tsx` (rendered once in `AppShell`, reading `lib/contextMenu.ts`): a popover for a mouse or the keyboard, a bottom sheet for touch. A row opts in with `useMenuTrigger(build, title)` (right-click, a 500ms press, the Menu key or Shift+F10; `build` runs when the menu opens, so it sees fresh state). A visible ⋮ calls `openMenuFrom`, and the menu leaves out actions already shown beside it (`omit`). Open the popover before measuring it (a closed `<dialog>` measures 0 wide). The entry card's ⋮ shows only on iOS (`isIos`), which sends no `contextmenu`. The FAB's menu is `anchored`: a pill per journal (`useNewEntryMenu`).
- What goes in each menu is `lib/menuActions.ts`. No Open (tapping is that). Hide an action that never applies; give `disabled` a reason for one blocked only for now (offline). Dialogs an action opens live in `components/ActionDialogs.tsx` (`openActionDialog`, ids only, so they read current data). An entry's Delete has no dialog: it goes to the trash and the toast offers Undo (`useDeleteEntry`); a journal's Delete confirms first. Entry pin, star and move go through `useEntryPatch`, so they queue offline. A button inside a row must not sit inside its link (the card wraps the link in a `relative` div).
- Toasts (`lib/toast.ts`) take a link (`{label, to}`) or a button (`{label, onClick}`, shown 6s instead of 3s).

## Shared pieces to reach for

Use these instead of copying markup:

- Layout and rows: `Page`, `ListRow` (lead, title, muted lines, trailing controls; a button, a link or plain text), `SectionHeader` (an icon in a tonal circle and a title), `EmptyState` (the cairn over a message).
- Entries: `EntryCard`, `MetaChip` and `EntryWhen` (the round chips under an entry, reader and editor), `EntryPaneHeader` and `FlagToggle` (the sticky entry bar; Pin and Star), `JournalBadge`, `JournalDot`, `JournalChip`, `MoodGrid`, `MoodBadge`, `entryLabel` (`packages/shared`: what to call an entry in a menu, toast or label).
- Forms and settings: `Textarea`, `PasswordInput` (every password field), `SwitchSetting`, `ChoiceSetting`, `ChoiceButtons`, `SettingText`, `ScopeNote`, `FilterChips`, `ConfirmDialog`, `DialogActions`, `TemplateDialog`, `PromptDialog`.
- Prompts: `CategoryChip`, `PromptRow`, `PromptCards`, `PromptBrowser`.
- Offline: `NeedsConnection` (stands in for a server-only page or block), `OfflineBanner` (atop a page partly disabled offline; `centered` for one line), `OfflineNote` (beside a disabled control).
- Hooks and helpers: `useCachedList` (`lib/cachedList.ts`: a server list that starts from a copy on the device), `useTip` (`lib/useTip.tsx`: a hover help bubble, mouse only, in the top layer), `useJournal(id)` / `journalById`, `useSettled` (run once a value stops changing), `useLoadMore` (infinite-scroll sentinel), `errorCode` (`lib/api.ts`), `plural` (`lib/format.ts`), `photoUrl` (`lib/photos.ts`), `copyText` (`lib/clipboard.ts`, with a fallback for plain http), `isCoarse` (`lib/pointer.ts`).

## Journal colours

- `lib/journalColors.ts`: `JOURNAL_COLORS` is the picker's 12 swatches, stored as `#rrggbb`; `journalColors.test.ts` keeps each pair apart (ΔE ≥ 14) and each swatch at 3:1 on the light and dark surfaces, so a new swatch must pass it. A journal with no colour falls back to `primary`.
- The colour marks _which journal_; the olive brand stays on the chrome (FAB, buttons, links, focus rings, logo). Raw colour is only for shapes (the `JournalBadge` circle, `JournalDot`, map pins, the empty-state cairn). Anything with text on it is a `journalWash(color, over, percent)` (a `color-mix` over a theme surface) with the theme's own text colour. `over` names a `--md-<role>` variable: Tailwind's `--color-*` twins are emitted only when a utility uses them, so a wash built on one can silently be transparent. A new wash goes in the test's `WASHES` (4.5:1 for its text).

## Entry text and cards

- Rendering goes through `components/Markdown.tsx`: react-markdown with `remark-gfm`, no raw HTML. `photo:<id>` resolves to `/api/photos/:id/display`, `attachment:<id>` to `AttachmentView` (inline elements only, since it sits in a paragraph), and other images show as links, never fetched. **Don't add `rehype-raw`.** Task boxes are read-only unless the caller passes `onToggleTask` (only the reader, for an entry in a live journal), which flips one character with `toggleTaskLine` and saves through `useEntryPatch`. `keepEmptyTasks` exists because remark-gfm drops the box of an item with no text.
- The entry font and size are per device (`lib/entryText.ts`, localStorage `cairn:entry-text`, applied as the module loads so the first paint is right; sets `--font-entry` and `--entry-scale`). The scale applies only to `.entry-body` and the editor; cards and excerpts keep fixed sizes on purpose. A new font goes in `ENTRY_FONTS` (shared), `ENTRY_FONT_OPTIONS` and `loaders`.
- The title/excerpt split is `summarize()` in `packages/shared/src/entryCard.ts` (a heading, or a first line of at most 80 characters, is the title). The excerpt is card text, not raw markdown. `EntryCard` links carry `previewOf(item)` as router state so the reader can show the title and date at once.

## Scroll

- `lib/scrollPlace.ts` is the one way to put a scroller back: `placeScroll(scroller, y)` keeps setting the position as the content grows until it is reached, the user scrolls, or 5s pass (a single `scrollTo` on a loading page gets clamped and the place is lost). **Nothing may save a position while `pending()`**: the clamped value is not where the user was.
- Two owners, never both on one route. The Entries screen (`isBrowsePath`) is `BrowseLayout`, which keeps a place per view and journal (`lib/browseView.ts`). Every other page scrolls the window, handled by `useWindowScroll` in `AppShell`: a push opens at the top, Back/Forward restores, a replace leaves it alone. A page needs no scroll code of its own.
- From `expanded` the list scrolls itself to the open entry's card when it is off screen (`lib/useRevealEntry.ts`, List view only), measuring against the `section[aria-label="Entries"]` pane, not the nearest `section`.

## Keyboard shortcuts

- What each shortcut is (keys, group, label, scope) is static in `lib/shortcutCatalog.ts`, so the help dialog can list every one from any screen. `lib/shortcuts.ts` joins behaviour to it: a screen calls `useShortcuts([{ id, when, run }])` with a catalogue id (or a whole `{ id, group, label, run }` for a palette-only command), and one listener (`ShortcutHost` in `AppShell`) matches presses. `ShortcutHost` also owns the shortcuts that are the same everywhere and renders the help (`?`, Ctrl/Cmd+/) and `CommandPalette` (Ctrl/Cmd+K). Both read the registry, so a new shortcut shows up in both; `palette: false` for ones that make no sense as a command.
- Keys are strings: steps separated by spaces (`g e` is a chord), `Mod` is Ctrl or Cmd. Matching is `lib/shortcutKeys.ts` (unit-tested): letters and digits with Mod or Alt match the physical key (`event.code`, since Option+letter types another character on a Mac), everything else `event.key`.
- The listener's rules: a bare key never fires in a text field or the editor (`inCodeEditor` opts one in) or while a `dialog[open]` is up (`inDialog`). Two per-device switches: quick-action keys (on by default) and the `g` go-to chords (off by default). On a collision the more specific `scope` wins (`editor` > `reader` > `browse` > `global`). It listens in the capture phase so it runs before CodeMirror's keymap, and `when`/`run` always read the latest render's closure. Keys CodeMirror handles itself are catalogued `helpOnly: true` (the `text.*` ids); add one only when it really works in `cm/MarkdownEditor.tsx`'s keymap.
- A screen with keys registers them itself; keep them out of `ShortcutHost` unless they are the same on every screen. **Delete and archive have no keys**: a bare key must never destroy anything unasked.

## Touch gestures

- Hand-written pointer handlers, no gesture library. `lib/useSwipe.ts` is the one horizontal-swipe hook (touch only; sets `touch-action: pan-y pinch-zoom`; `onDrag(dx)` lets content follow the finger). It ignores a swipe that starts within 24px of the screen edge (iOS's back swipe), inside an element that scrolls sideways, or inside `data-no-swipe`: put that on anything with its own horizontal drag (a map, the editor, the Lightbox).
- `layout/EntriesPane.tsx` swipes between views: only the content wrapper moves (never the header), its transform is cleared at rest (a transform on an ancestor breaks the views' sticky bars), and it sits in an `overflow-x-clip` wrapper, without which a phone widens its layout viewport mid-slide and the fixed bottom bar jumps. **Any new sideways-moving content needs the same clip.** The map is entered by swipe but never left by it. There is deliberately no swipe to open the drawer and no swipe actions on rows (long press covers them).
- The reader swipes to the older and newer entry (`components/EntrySwipe.tsx`, `/entry/:id` only); `lib/useEntryFlip.ts` is the one neighbour lookup for the swipe and j/k. The Lightbox has its own two-axis gesture code (pure parts in `lib/lightboxGestures.ts`). Insights' cards swipe through `lib/useSlideSwipe.ts`.
- Every `state-layer` control also gets an invisible hit area of at least 44px (`tap-target`, only under `pointer: coarse`); a positioned control with no state layer takes `tap-target` alone. A scroll container whose rows sit flush against its edges takes `-my-1 py-1`, or the hit areas count as overflow and it grows a phantom scrollbar. `e2e/touch.spec.ts` checks nothing scrolls sideways because of them.
- `touch-action: manipulation` is on `:root`. `lib/haptics.ts` `tick()` is a 2ms vibration on a view switch. The sticky offsets (`top-25`, `scroll-mt-*`) assume the Entries `TopBar` and `ViewSwitch` are 56px and 44px with no gap.

## Features

- **Entries views:** `components/ViewSwitch.tsx` (Details, List, Calendar, Media, Map), the choice per device in `lib/browseView.ts`, picked in `layout/EntriesPane.tsx`. Add a view by extending `BROWSE_VIEWS`, `ViewSwitch` and `EntriesPane`. A tag filter (`?tag=`) shows the List whatever the view (the others don't filter); choosing another view goes through `useChooseView`, which drops it. Details, Calendar and Media need the server.
- **Calendar** (`components/CalendarView.tsx`): a grid per month, oldest first, from `/insights/first-month`. Every grid renders from the start so the page keeps its height, and each month fetches its days only when within 1000px of the screen. It skips its jump to this month when returning to a saved place.
- **Month jump** (`MonthJumpDialog`, from a month header in `TimelineList`): loads pages until that month is loaded, then scrolls to it.
- **Map** (`components/EntriesMap.tsx`, lazy, Leaflet 1.9 with markercluster): always import Leaflet through `lib/leaflet.ts`, which sets `window.L` before the cluster plugin. Leaflet's CSS loads after `index.css`, so map styles there are scoped `div.leaflet-container …`. Pin cards are built from DOM nodes, never HTML. The tile layer sets `referrerPolicy` (the app's `no-referrer` would strip what OpenStreetMap's rules ask for), and CSP `img-src` allows `tile.openstreetmap.org`; another tile server needs a CSP change. The opening view is the densest area (`lib/mapFocus.ts`), framed once per journal.
- **Insights** (`pages/InsightsPage.tsx`): computed by the server, not kept offline. "Today" is the account timezone's day, sent by the client. Moods aren't a linear scale, so only valence is ever averaged. From `expanded` an entry opens in `EntryPopup`, a history state on the same URL (`lib/entryPopup.ts`), so Back closes it and the page keeps its scroll.
- **Prompts** (design: `docs/design/prompts-proposal.md`): online only, except that the lists start from a copy on the device (`useCachedList`). Daily prompts and category picks are shuffle bags in localStorage (`lib/dailyPrompts.ts`, pure and unit-tested). A prompt opens `/new?prompt=<text>`, whose heading is the editor's baseline (see the editor notes). Suggested categories start collapsed (a library can hold hundreds). Bulk delete deletes only selected prompts that are still shown.
- **Trash** (`pages/TrashPage.tsx`, `lib/trash.ts`): needs the server, except the "Waiting to move to Trash" section (deletes queued offline). Wording uses `me.trashRetentionDays`.
- **Tags:** a draft field compared with `sameTags` (order and case ignored), sent whole only when changed. The last list read online is remembered (`cairn:tags-cache:<userId>`) so suggestions work offline. Managing tags (`pages/TagsPage.tsx`) needs the server; `invalidateAfterTagChange` re-reads lists, search and open entries.
- **Templates** (`pages/TemplatesPage.tsx`, `lib/templates.ts`): text only, per user. In `TemplateDialog` Enter in the name field never submits (the dialog also sits in the editor's form). The pure side is `lib/templateText.ts` (placeholders `{{date}}`, `{{time}}`, `{{datetime}}`, `{{weekday}}`, filled at insert time on the entry's timezone). `lib/cachePrefixes.ts` has **no imports on purpose**: importing `cachedList.ts` there made an import cycle that left the whole app blank.
- **Manage users, Storage:** admin pages read afresh from the server on each visit; an admin's own row points to Account.
