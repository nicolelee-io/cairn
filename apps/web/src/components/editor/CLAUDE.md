# Editor

- `EntryEditor.tsx` serves `/new` and `entry/:id/edit` (under `/` or `/j/:journalId`) in the reader pane; `useBrowseParams().editing` is true there and the bottom bar and FAB hide. Entries in an archived journal don't open in it.
- `EntryEditor.tsx` is the layout and the dialogs; the state lives in two hooks beside it. `useEntryDraft.ts` owns the working copy (`fields`, `baseline`, `baseRev`, `dirty`), the draft restore and autosave, and `settle()`, `resetToBaseline()`, `adoptTheirs()` and `adoptSaved()`. `useSaveEntry.ts` owns the Save mutation (POST, or PATCH of the changed fields plus `baseRev`; the outbox fallback; conflict and error mapping). Keep new draft or save logic in these, not in the component. The footer chips are `EntryMetaBar.tsx` (journal, date, place, weather, tags); the dialogs they open stay in `EntryEditor`, which also opens them from shortcuts.
- **Drafts are localStorage only** (`lib/draft.ts`, key `cairn:draft:<userId>:<entryId>`), debounced 800ms and flushed on pagehide, visibilitychange and unmount. A new entry's id is minted client-side up front: it is the draft's slot (so several new-entry drafts coexist; `/new?draft=<id>` resumes one, `/new` is always blank) and makes a retried create idempotent. Nothing reaches the server until Save, so no empty entries get created. `pages/DraftsPage.tsx` lists them.
- **Baseline, not edits:** a starting value the user didn't type goes in the baseline, so an untouched entry isn't dirty, saves no draft and closes without asking. `/new?prompt=<text>` makes `promptHeading(text)` the baseline (caret after it, `caretAtEnd`); auto location on a new entry fills the fields and the baseline.
- Save: POST for a new entry (needs text), PATCH with only the changed fields plus `baseRev` for an edit. A 409 `conflict` rebases `baseRev` and shows the server's text; "Use theirs" or "Keep mine" is the user's explicit choice. Mod+S saves and stays (a new entry's first save moves to its edit route with `state.keepFocus`); a save parked in the outbox closes regardless.
- There is no title field: the title is the first line (`summarize()`). Source mode (`lib/editorMode.ts`, per device) shows plain markdown with no in-place styling; there is no separate preview. Zen mode is called immersive in the code (`lib/immersive.ts`): the editor's flag is sticky per device, the reader's is not, and the two don't affect each other.
- Date and time: `lib/entryTime.ts` does the zone maths; the wall clock is kept when only the zone changes. `components/ui/select.tsx` is the themed replacement for native selects.
- Header button tips use `useTip` and end with the key from `shortcutHint(id)` (`lib/shortcutCatalog.ts`), so a rebound key can't leave a stale tip. The tip replaces a `title` attribute, except on a disabled button (no pointer events, so no tip), where `FlagToggle` keeps the native `title`. Accessible names stay fixed; the tip text follows state.

## CodeMirror

- `cm/MarkdownEditor.tsx` is controlled like a textarea (`value`/`onChange`). External changes carry an annotation so they aren't echoed, and a `value` it reported itself is never written back even when it lags the doc (`reported`); without that, keys typed faster than React renders were dropped. It exposes `EditorHandle` (`focus`, `hasCaret`, `edit`, `undo`, `redo`, `completionOpen`). **Write the document only through `EditorHandle.edit` or the `value` prop**, never around CodeMirror, so undo stays CodeMirror's own history.
- `cm/livePreview.ts` is a StateField of decorations from the Lezer markdown tree: marks styled in place, markers hidden unless the caret touches them. A photo or attachment reference alone on its line is a block widget (`MediaWidget`); inside a line it stays source text. A task's `- [ ] ` is one atomic checkbox widget (`taskField`). Links open on Ctrl/Cmd+click or the "Open link" pill (touch has no Ctrl+click), through `lib/externalHref.ts`, shared with the reader. Pipe tables stay plain text in monospace.
- Inline marks: bold `**`, italic `*` (not `_`, which doesn't italicise inside a word), strikethrough `~~`. A divider is `---` inserted as its own block with a blank line above (right under text it would be a Setext heading). All formatting is pure in `lib/markdownEdit.ts`, shared by the toolbar, the keys and the slash menu.
- The text fills the column down to the chips: the host and wrapper are flex columns and the theme sets `.cm-scroller` to `align-items: stretch !important` (CodeMirror's base theme says flex-start with `!important`). Keeping the caret clear of the toolbar is CodeMirror's `scrollMargins` (`bottomMargin`). Keyboard autocorrect needs `autocorrect: 'on'` in `contentAttributes`.
- Paste and drop of files call `onFiles` (`lib/useUploads.ts`); Save is disabled while an upload runs.

## Toolbar

- Defined once in `toolbarMenus.ts`, four groups (Heading, Text styling, Lists and blocks, Attachments; a new insert goes in the group it belongs to). `isCoarse()` picks the layout: on touch four group buttons, a Templates button and undo/redo, above the keyboard (`lib/useKeyboardInset.ts` for iOS, `interactive-widget=resizes-content` on Chrome Android), each group opening an inline `ToolPanel` row (a plain div, not a dialog, so the keyboard and caret are undisturbed); with a mouse every choice is its own button, and groups fold into menus as the row narrows (`foldedGroups` in `toolbarLayout.ts`, pure and unit-tested; its pixel sums must match the markup). Undo and redo stay pinned at the right. The seven touch buttons fit a 360px phone because buttons are 44px under 380px wide; `toolbar.spec.ts` checks it.
- The toolbar never takes focus (buttons cancel pointer-down). Photos and Files are separate buttons because a phone opens its photo picker only for `image/*` alone (`PHOTO_ACCEPT`/`FILE_ACCEPT` in `lib/upload.ts`).
- e2e goes through `choose()` in `toolbar.spec.ts`, which presses a choice's button if shown and otherwise opens its group.

## Keys

- Registered in `EntryEditor` with `useShortcuts` (scope `editor`). The registry's listener runs before CodeMirror's keymap, so **a new editor key goes in `lib/shortcutCatalog.ts` and `useShortcuts`, never in CodeMirror's keymap**.
- The scheme: Mod+key is a universal action (save, palette, link, bold, italic, help); Mod+Shift is text blocks plus Save and close (Mod+Shift+S); Mod+Alt is the heading digits (avoid Mod+Alt+letter: where AltGr is Ctrl+Alt it would block typing); Alt+Shift+letter is everything about the entry (date, place, mood, tags, weather, journal, …). Not plain Alt, which Chrome takes for the address bar and menu on Windows and Linux. Mod+Enter is deliberately not Save. Esc closes (asking first when dirty), except while the slash menu is open (`completionOpen()`), when it reaches CodeMirror.
- Focus: a dialog opened by its key starts on its main control and hands focus back to the text; one opened from a chip returns to the chip. Tab leaves the text for the chips, as in Day One. Lists and grids move with `lib/moveFocus.ts` (one tab stop per grid).

## Templates and slash menu

- `TemplatesButton.tsx` (`useTemplatesMenu` owns the rows, the Save as template dialog and the palette commands): a header button with a mouse, the toolbar's fifth button on touch, both opening the shared context menu. Templates insert through `insertItem`; Save as template strips photo and file references (`withoutMedia`).
- Slash menu (`cm/slashCommands.ts`, a CodeMirror `autocompletion`; items in `lib/insertItems.ts`, the user's templates first): `/` opens only at the start of a line or after whitespace, and only when a word follows, so `and/or` and `yes / no` are left alone. `matchItems` filters by label or keyword prefix (`filter: false`, since CodeMirror's fuzzy match ignores keywords); sections carry a `rank` to keep the list's order. A pick is one change (`applySlash`, `diffEdit`), so one undo takes it back. Date items use the current moment on the entry's timezone; `shiftedDate` counts calendar days so DST can't skip one. `insertSnippet` sets a block template apart with blank lines so it can't glue onto a heading. A new built-in goes in `BUILT_IN_ITEMS`.
- The popup's styles are in `MarkdownEditor`'s `theme`, every selector repeating `.cm-tooltip.cm-tooltip-autocomplete` (or the base theme wins); its scrollbar is in `index.css`. CodeMirror ignores Enter for 75ms after the menu opens (`interactionDelay`; e2e waits for it).
- **The slash menu doesn't work on a real Android phone** (likely Gboard composing the word after the slash). Accepted: the Templates button covers touch. The e2e phone project doesn't reproduce it, so its slash tests passing says nothing about a real phone.
